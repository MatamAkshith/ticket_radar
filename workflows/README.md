
# Foundation — Engineering Workflows

This directory contains the standardized engineering processes used by Foundation.

These documents describe how development activities should be organized, coordinated and completed.

## Available Workflows

| Workflow | Purpose |
|---|---|
| 01 - New Project | Develop a new software project |
| 02 - Existing Project | Understand and onboard an existing repository |
| 03 - Feature Development | Implement and verify individual features |
| 04 - Bug Fixing | Investigate and resolve software defects |
| 05 - Autonomous Sprint | Execute a bounded set of development tasks |
| 06 - Release Verification | Assess software release readiness |

## How Workflows Are Used

- The Engineering Orchestrator identifies the appropriate workflow.
- Relevant Skills provide the detailed execution procedures.
- Specialist Agents perform focused engineering responsibilities.
- Engineering Rules establish implementation standards.
- Project_Notes.md maintains persistent project context.

## Standard Engineering Lifecycle

UNDERSTAND → INSPECT → PLAN → IMPLEMENT → VERIFY → DOCUMENT → COMMIT → REPORT

## Git Policy

Foundation supports automated local commits after successful verification.

Remote pushes require explicit user authorization.

## Important

These documents describe processes. They do not independently execute commands or create agent capabilities.
